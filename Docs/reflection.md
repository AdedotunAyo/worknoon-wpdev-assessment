System Thinking and Project Reflection

Problem Overview

The objective of this project was to build a functional WordPress landing page while demonstrating practical understanding of SEO, structured data, and system-level thinking. The task was not just about design, but about showing how different parts of a web system work together to support growth, performance, and discoverability.

Approach to the Solution

I approached the project with a focus on simplicity, clarity, and performance. Instead of building a complex multi-page site, I created a focused landing page that highlights key sections such as services, testimonials, and a contact form.

At the same time, I ensured that the technical aspects of the project were properly handled, including analytics integration, structured data preparation, and performance optimisation.

Architecture, Tools and Plugins

The project was built using WordPress with the Divi Builder for layout and design. This allowed for rapid development and easy control over responsiveness.

Key tools and plugins used:

* Divi Builder for page structure and design
* Forminator for handling contact form submissions
* Site Kit by Google for analytics integration

Custom CSS was also used to refine the visual design and improve user interface elements.

Key Decisions and Rationale

One of the main decisions was to keep the design minimal and focused. Instead of adding unnecessary features, I prioritised clarity, speed, and usability.

Another key decision was to structure the content as an SEO-focused service page. This made it easier to align the project with the requirements around schema, indexing, and search visibility.

I also chose to separate layout, styling, and documentation clearly within the repository to make the project easy to understand and reproduce.

Tradeoffs Considered

Using Divi allowed for faster development but comes with some performance overhead compared to a fully custom build. This was balanced by applying optimisation practices such as image compression and limiting unnecessary plugins.

Using plugins instead of custom-built features reduced development time but introduces some dependency on third-party tools. This tradeoff was acceptable given the scope of the assessment.

Challenges Encountered

One challenge was ensuring that the project remained simple while still meeting all the requirements. It is easy to overbuild, but the focus here was on clarity and execution.

Another challenge was handling schema correctly without introducing incorrect or assumed data. This required careful validation of available information and avoiding guesses.

How the Challenges Were Resolved

To manage complexity, I kept the structure minimal and focused only on required sections. For schema, I used only verified data from the website source and avoided adding unconfirmed details.

Performance challenges were handled by optimising assets and using caching where possible.

System Thinking Considerations

The project was approached as a system rather than just a page. This includes:

* User flow from landing page to contact form
* Data collection through the form
* Analytics tracking for performance measurement
* Structured data to support search engine understanding

Each part was designed to work together to support business goals such as lead generation and visibility.

Affiliate Tracking and Onboarding Systems

Although not fully implemented, a scalable approach would involve tracking user referrals through unique links or parameters. This could be integrated using external platforms or custom tracking logic.

An onboarding system could include automated email responses and user segmentation based on form submissions.

Experience with Tools like FirstPromoter

I understand how affiliate tracking systems work, including the use of referral links, event tracking, and conversion attribution. These systems can be integrated into WordPress using scripts or API connections.

What I Would Improve

If I were to rebuild the project, I would consider using a lighter builder or native WordPress blocks to further improve performance. I would also expand the schema implementation to include additional types such as FAQ and breadcrumbs.

More advanced tracking and automation could also be added to improve data collection and user engagement.

Final Reflection

This project demonstrates my ability to build a functional WordPress solution while considering SEO, performance, and system design. The focus was on creating a clean, scalable structure that aligns with real-world requirements.
